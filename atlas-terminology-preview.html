⑩ Guardrails & what's out of scope

Hard guardrails the relabel respects

  • No banned legacy terms reintroduced. The safety scanner flags these; none appear in any proposed copy above: blind spot, evasion rate, fraud playbook, patch, budget, attack, exploit. (e.g. we say "weak spot" not "blind spot", "stress test" not "attack", "fix" not "patch".)
  • Canonical terms stay visible. Every plain headline keeps its technical term underneath, satisfying the project terminology standard and the dual-audience invariant.
  • Synthetic-currency safety preserved. Every money figure keeps the SYN $ prefix.
  • Immutable labels untouched: RetailBank-X, Mock Account-Takeover Risk Scorer, instant_transfer, etc.
  • Where copy lives: a small central label map (extending the existing FIX_TYPE_LABELS / DECISION_ACTION_LABELS pattern in app/web/lib/formatters.ts) plus the per-component TS constants. Keeps it inspectable by make safety-scan.

Out of scope (per your "UI display layer only" + "relabel only" choices)

  • API field names, Pydantic schemas, ledger keys — unchanged. They're load-bearing contracts.
  • The raw judge_notes condition string (e.g. accepted=False; recall_improves=False(recall_lift=0.0); …) is generated server-side in src/atlas/judge/acceptance.py. We relabel its header only; rewriting the string itself would mean touching generated text (the option you set aside). Flagging it as the one remaining eyesore if you ever want a follow-up.
  • Generated transcript & final-report prose in src/atlas/ledger/report_builder.py — left as-is.
  • No new intro / glossary / walkthrough sections — relabel only.
